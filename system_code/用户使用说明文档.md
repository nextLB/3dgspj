## 1. 系统概述

本系统是 [VastGaussian](https://github.com/kangpeilun/VastGaussian)（大规模场景三维高斯泼溅重建）的 **Web 图形化管理界面**，基于 Django 开发。它将 VastGaussian 的命令行工具链封装成可视化的表单操作，让你无需手动拼接命令即可完成三维重建的全流程。

### 系统能做什么

| 功能 | 说明 |
|------|------|
| 用户管理 | 注册/登录，普通用户与管理员角色 |
| **数据预处理** | 将原始图片通过 COLMAP 自动处理为标准数据集格式 |
| 数据集管理 | 导入/管理 COLMAP/Blender 格式的数据集 |
| **训练 (Train)** | 调用 `train_vast.py` 执行分块并行训练 |
| **渲染 (Render)** | 调用 `render.py` 生成渲染图像 |
| **评估 (Eval)** | 调用 `metrics.py` 计算 PSNR/SSIM/LPIPS 指标 |
| 任务监控 | 实时查看日志、状态刷新、终止任务 |
| 结果管理 | 自动解析并存储评估结果 |

### 涉及的后端程序

| 操作 | 调用的 VastGaussian 脚本 | 所在位置 |
|------|------------------------|----------|
| Preprocessing | `VastGaussian/convert.py` | VastGaussian 根目录 |
| Training | `VastGaussian/train_vast.py` | VastGaussian 根目录 |
| Rendering | `VastGaussian/render.py` | VastGaussian 根目录 |
| Evaluation | `VastGaussian/metrics.py` | VastGaussian 根目录 |
| 数据分区 | `VastGaussian/utils/partition_utils.py` | 被 train_vast.py 自动调用 |
| 无缝合并 | `VastGaussian/seamless_merging.py` | 训练完成后自动调用 |
| 曼哈顿变换 | `VastGaussian/utils/manhattan_utils.py` | 被 train_vast.py/render.py 自动调用 |

## 2. 快速上手

### 2.1 启动系统

```bash
cd /home/next_lb/桌面/next/三维重构/code/3dgspj/system_code
conda activate vasgaussian_system
python manage.py runserver 0.0.0.0:8000
```

浏览器打开 `http://127.0.0.1:8000`

### 2.2 创建账号

点击 **注册**，填写用户名、邮箱、密码即可注册。管理员后台账号：`admin / admin123`

### 2.3 准备数据

你的数据可以是两种状态之一：

#### 方案 A：已有 COLMAP 标准格式数据

```
datasets/你的场景/
├── images/          # 输入图片（JPG/PNG）
├── sparse/          # COLMAP 稀疏重建结果
│   └── 0/
│       ├── points3D.bin (或 .txt)
│       ├── cameras.bin
│       └── images.bin
```

直接进入 2.4 步导入数据集即可。

#### 方案 B：只有原始图片（推荐使用系统预处理功能）

你的原始图片目录结构可能是这样：

```
datasets/domitory/
├── A/               # 多个子目录，各存不同视角的图片
│   ├── A001.JPG
│   └── ...
├── D/
├── S/
├── W/
└── X/
```

或者所有图片直接散落在目录下：

```
datasets/my_scene/
├── IMG_0001.jpg
├── IMG_0002.jpg
└── ...
```

此时使用系统的 **数据预处理** 功能来处理（见 2.3.1 节）。

### 2.3.1 使用系统预处理功能

> 进入顶部导航栏 **「预处理」** 或 **数据集 → 数据预处理**

1. **原始图片目录**：填写你的图片文件夹路径
2. **数据集名称**：处理完成后在系统中创建的数据集叫什么
3. **合并子目录图片**：勾选后将自动把 A/D/S/W/X 等子目录中的图片合并到 `input/`
4. **相机模型**：默认 OPENCV，一般无需修改
5. 点击 **开始预处理**

系统后台会自动执行：
```
合并图片 → COLMAP 特征提取 → 特征匹配 → 稀疏重建 → 图像去畸变
```

处理过程中数据集列表会显示 **「预处理中」**（带旋转动画），完成后变为 **「就绪」**。

处理后目录结构变为：
```
domitory/
├── input/           ← 原始图片（合并后的）
├── images/          ← COLMAP 去畸变后的图片（供训练使用）
├── sparse/0/        ← COLMAP 稀疏重建结果
│   ├── points3D.bin
│   ├── cameras.bin
│   └── images.bin
├── distorted/       ← COLMAP 中间文件
```

### 2.4 导入数据集

对于已经是 COLMAP 格式的数据：
进入 **数据集** 页面 → **导入数据集** → 填写名称和路径

系统预处理完成后会自动创建数据集记录，无需手动导入。

### 2.5 创建项目并训练

1. 进入 **项目** → **新建项目**
2. 选择数据集或手动输入路径
3. 设置训练参数（分区数、迭代次数、曼哈顿对齐等）
4. 点击 **创建项目**
5. 在项目详情页点击 **训练** 按钮
6. 等待训练完成（可实时查看日志）

### 2.6 渲染与评估

训练完成后：
- 点击 **渲染** → 设置迭代次数 → 生成渲染图像
- 点击 **评估** → 自动计算 PSNR / SSIM / LPIPS

## 3. 界面参数与 VastGaussian 参数对照表

### 3.1 预处理参数区

| 界面字段 | 对应命令行参数 | 对应代码位置 | 说明 |
|---------|--------------|------------|------|
| 原始图片目录 | `-s` / `--source_path` | `convert.py:source_path` | 图片所在目录 |
| 数据集名称 | — | Dataset.name | 处理后创建的数据集名称 |
| 合并子目录图片 | — | 系统内部处理 | 自动递归子目录合并图片到 input/ |
| 相机模型 | `--camera` | `convert.py:camera` | OPENCV/PINHOLE/SIMPLE_RADIAL |
| 生成缩放图片 | `--resize` | `convert.py:resize` | 同时生成多分辨率版本 |

### 3.2 基本信息区

| 界面字段 | 对应命令行参数 | 对应代码位置 | 说明 |
|---------|--------------|------------|------|
| 项目名称 | — | Project.name | 仅用于界面展示 |
| 实验名称 | `--exp_name` | `arguments/__init__.py:ModelParams.exp_name` | 输出文件夹名 |
| 数据集路径 | `-s` / `--source_path` | `arguments/__init__.py:ModelParams._source_path` | 数据目录绝对路径 |

### 3.3 训练参数区

| 界面字段 | 对应命令行参数 | 对应代码位置 | 默认值 | 说明 |
|---------|--------------|------------|-------|------|
| 训练迭代数 | `--iterations` | `OptimizationParams.iterations` | `30_000` | 总迭代次数 |
| 分辨率缩放 | `--resolution` | `ModelParams._resolution` | `-1` | -1=自动，1=原始，2=1/2，4=1/4 |
| LLFF 测试间隔 | `--llffhold` | `ModelParams.llffhold` | `83` | 每 N 张选 1 张做测试 |
| 评估模式 | `--eval` | `ModelParams.eval` | `False` | 开启后划分训练/测试集 |
| 白色背景 | `--white_background` | `ModelParams._white_background` | `False` | Blender 数据使用 |
| 安静模式 | `--quiet` | 无对应，抑制打印输出 | `False` | — |

### 3.4 数据分区参数区

这些参数对应 VastGaussian **核心创新**：渐进式数据分区（Progressive Data Partitioning）

| 界面字段 | 对应命令行参数 | 对应代码位置 | 默认值 | 说明 |
|---------|--------------|------------|-------|------|
| X方向分区数 | `--m_region` | `ModelParams.m_region` | `3` | 沿 X 轴切分的块数 |
| Z方向分区数 | `--n_region` | `ModelParams.n_region` | `3` | 沿 Z 轴切分的块数 |
| 边界扩展率 | `--extend_rate` | `ModelParams.extend_rate` | `0.2` | 每个分区的边界扩展比例，用于无缝合并 |
| 可见性比率 | `--visible_rate` | `ModelParams.visible_rate` | `0.25` | 空域感知可见性阈值 |

**说明**：`m_region × n_region` 即总分区数。例如 3×3=9 个分区。每个分区会独立训练，最后通过 `seamless_merging.py` 无缝合并。总分区数不能超过 GPU 数量太多（否则排队训练）。

**涉及代码**：
- `scene/vastgs/data_partition.py` — 核心分区算法
- `utils/partition_utils.py` — 分区调度入口

### 3.5 曼哈顿对齐参数区

曼哈顿对齐（Manhattan World Alignment）是 VastGaussian 的关键前置步骤。目的是将场景点云摆正，使 Y 轴垂直于地面，X/Z 轴平行于建筑边界。

| 界面字段 | 对应命令行参数 | 对应代码位置 | 说明 |
|---------|--------------|------------|------|
| 启用曼哈顿对齐 | `--manhattan` | `ModelParams.manhattan` | 开关 |
| 对齐平台 | `--platform` | `ModelParams.platform` | `cc`=CloudCompare，`tj`=Three.js |
| 平移向量 | `--pos` | `ModelParams.pos` | 3 个 float 值 |
| 旋转矩阵/角度 | `--rot` | `ModelParams.rot` | cc=9元素矩阵，tj=3个欧拉角 |

**涉及代码**：`utils/manhattan_utils.py`

#### 使用 Three.js 对齐

1. 打开 https://threejs.org/editor/
2. File → Import 导入初始点云（PLY 格式）
3. 在右侧编辑区调整位置和旋转，使地面垂直于 Y 轴
4. 从编辑区读取 Position 三个值填入 **pos**，Rotation 三个值填入 **rot**
5. 平台选择 **tj**

#### 使用 CloudCompare 对齐

1. 导入点云到 CloudCompare
2. 用 Translate/Rotate 工具调整姿态
3. 从控制台读取变换矩阵
4. 前 3 个平移值填入 **pos**，3×3 旋转矩阵的 9 个元素填入 **rot**
5. 平台选择 **cc**

## 4. 完整工作流程

### 4.1 流程全景图

```
原始图片（A/D/S/W/X 多子目录或单目录）
    │
    ▼
数据预处理（系统内操作）               # Web 界面：预处理页面
    │
    ├─ 合并子目录图片 → 生成 input/
    ├─ 运行 COLMAP (convert.py)
    │   ├─ 特征提取
    │   ├─ 特征匹配
    │   ├─ 稀疏重建
    │   └─ 图像去畸变
    └─ 自动创建数据集 → 状态「就绪」
    │
    ▼
导入更多数据集 / 选择已有数据集        # Web 界面：数据集页面
    │
    ▼
创建项目 → 配置参数                    # Web 界面：创建项目页面
    │
    ▼
点击「训练」
    │
    ├─ 1. 曼哈顿对齐 (get_man_trans)   # manhattan_utils.py
    ├─ 2. 数据分区 (data_partition)     # partition_utils.py → data_partition.py
    ├─ 3. 多 GPU 并行训练               # train_vast.py → parallel_local_training()
    │   └─ 每个分区独立训练 (PartitionScene)
    ├─ 4. 无缝合并 (seamless_merge)     # seamless_merging.py
    └─ 完成
    │
    ▼
点击「渲染」                           # render.py
    │
    ▼
点击「评估」                           # metrics.py
    │
    ▼
查看 PSNR / SSIM / LPIPS 结果
```

### 4.2 预处理阶段详细时序

当你在 **数据集** 页面点击 **数据预处理** → **开始预处理** 时，系统执行：

```
1. 后台线程启动 (threading.Thread)
2. 合并子目录图片：
   ├─ 扫描 source_path/ 下所有子目录（如 A/D/S/W/X）
   ├─ 复制 .jpg/.jpeg/.png 图片到 source_path/input/
   └─ 统计复制数量
3. 创建 Dataset 记录（状态: processing）
4. 构造命令: python convert.py -s source_path
5. 启动子进程 (subprocess.Popen)
6. convert.py 内部执行:
   ├─ COLMAP feature_extractor    # 特征提取
   ├─ COLMAP exhaustive_matcher   # 特征匹配
   ├─ COLMAP mapper               # 稀疏重建
   └─ COLMAP image_undistorter    # 图像去畸变
7. 日志实时写入文件 → 界面刷新显示
8. 进程退出:
   ├─ 成功 → Dataset 状态变为 ready, 统计图片数
   └─ 失败 → Dataset 状态变为 failed
```

### 4.3 训练阶段详细时序

当你在项目详情页点击 **训练** 按钮时，系统执行：

```
1. 后台线程启动 (threading.Thread)
2. 构造命令: python train_vast.py [所有参数]
3. 启动子进程 (subprocess.Popen)
4. train_vast.py 内部执行:
   ├─ get_man_trans(lp)           ← 曼哈顿对齐矩阵
   ├─ prepare_output_and_logger() ← 创建输出目录
   ├─ data_partition(lp)          ← 场景分区
   │   ├─ sceneLoadTypeCallbacks["Partition"]
   │   └─ ProgressiveDataPartitioning
   ├─ 多进程并行训练 (每个分区一个进程):
   │   ├─ PartitionScene 加载分区数据
   │   └─ training() 执行 3DGS 训练循环
   └─ seamless_merge()            ← 合并所有分区
5. 日志实时写入文件 → 界面刷新显示
6. 进程退出 → 状态标记为「训练完成」
```

### 4.4 渲染阶段

```
1. 构造命令: python render.py [相关参数]
2. render.py 内部:
   ├─ Scene_Eval 加载训练好的模型
   ├─ render_sets() 遍历所有相机
   └─ 保存渲染图像到 output/[exp_name]/test/
```

### 4.5 评估阶段

```
1. 构造命令: python metrics.py -m output/[exp_name]
2. metrics.py 内部:
   ├─ readImages() 读取渲染图像和 GT
   ├─ color_correct() 颜色校正
   ├─ 计算 SSIM / PSNR / LPIPS
   └─ 保存 results.json 到输出目录
3. 系统自动解析 results.json → EvaluationResult 模型
```

## 5. 后台程序调用关系

### 5.1 核心程序与路径

| 文件 | 角色 | 被调用时机 |
|------|------|-----------|
| `VastGaussian/convert.py` | COLMAP 预处理 | 点击「数据预处理」 |
| `VastGaussian/train_vast.py` | 训练入口 | 点击「训练」 |
| `VastGaussian/render.py` | 渲染入口 | 点击「渲染」 |
| `VastGaussian/metrics.py` | 评估入口 | 点击「评估」 |
| `VastGaussian/seamless_merging.py` | 无缝合并 | train_vast.py 训练结束后自动调用 |
| `VastGaussian/utils/manhattan_utils.py` | 曼哈顿变换 | train_vast.py / render.py 启动时调用 |
| `VastGaussian/utils/partition_utils.py` | 数据分区 | train_vast.py 启动时调用 |
| `VastGaussian/scene/vastgs/data_partition.py` | 分区算法 | 被 partition_utils.py 调用 |
| `VastGaussian/scene/vastgs/appearance_network.py` | 外观解耦网络 | 训练循环中调用 |
| `VastGaussian/arguments/__init__.py` | 参数定义 | 所有脚本 |
| `VastGaussian/scene/__init__.py` | Scene/PartitionScene | 数据加载 |

### 5.2 Django 后端调用链

```
projects/views.py
    ├─ preprocess()                → 预处理入口
    │   ├─ (合并子目录图片 → input/)
    │   ├─ _build_convert_cmd()    → 拼装 convert.py 命令
    │   └─ _run_convert_job_thread() → 后台线程执行 COLMAP
    │
    ├─ _build_train_cmd()          → 拼装 train_vast.py 命令
    ├─ _build_render_cmd()         → 拼装 render.py 命令
    ├─ _build_eval_cmd()           → 拼装 metrics.py 命令
    │
    ├─ _run_job_thread()           → 后台线程（训练/渲染/评估）
    │   ├─ subprocess.Popen()      → 实际启动 VastGaussian 脚本
    │   └─ 实时捕获 stdout → 写日志文件
    │
    └─ _parse_and_save_eval_results() → 解析 results.json
```

## 7. 常见问题

### Q: 预处理时报错 "COLMAP not found"

当前 conda 环境没有安装 COLMAP。安装方法：

```bash
conda install -c conda-forge colmap
# 或
pip install pycolmap
```

### Q: 训练时报错 "CUDA out of memory"

- 降低 `--resolution` 值（设为 4 或 8）
- 降低 `m_region × n_region` 分区数
- 将 `data_device` 改为 `cpu`

### Q: 数据分区时报错 "Manhattan alignment not performed"

- 开启 **曼哈顿对齐** 并填写正确的 pos/rot 参数
- 或使用 Three.js / CloudCompare 获取对齐参数

### Q: 如何查看训练进度？

- 项目详情页的 **训练日志** 区域实时显示终端输出
- 任务详情页有完整日志
- 状态徽章会自动刷新（训练中 → 已完成）

### Q: 训练完成后输出在哪里？

默认在 `VastGaussian/output/[实验名称]/` 目录下：
- `point_cloud/` — 各迭代步的点云
- `test/ours_60000/renders/` — 渲染图像
- `test/ours_60000/gt/` — 真实图像
- `results.json` — 评估指标
- `partition_point_cloud/` — 各分区数据

### Q: 如何在多 GPU 上训练？

系统自动检测可用 GPU。`train_vast.py` 内部会自动将分区分配到不同 GPU 上并行训练。如果有 4 块 GPU 和 3×3=9 个分区：
- 第 1 轮：GPU 0-3 训练分区 0-3
- 第 2 轮：GPU 0-3 训练分区 4-7
- 第 3 轮：GPU 0 训练分区 8

### Q: 预置数据集的完整训练命令（参考）

### Q: 我的数据集有 A/D/S/W/X 多个子目录，怎么处理？

使用系统的 **数据预处理** 功能：
1. 进入导航栏 **预处理**
2. 原始图片目录填 `.../domitory`
3. **合并子目录图片** → ✅ 开启
4. 点击 **开始预处理**
5. 系统自动将 5 个子目录的图片合并，然后执行 COLMAP
6. 完成后直接用于创建项目训练
